The model

Less machinery.
More Git.

madm keeps the proven bare-repository approach and adds help only where a home-directory work tree needs extra care. There is nothing to deploy and no private state to decode.

01

The real files

Applications read the same files Git tracks. No mirror, staging directory, or generated home tree sits in between.

02

The real Git

Commands, aliases, configuration, hooks, remotes, and credentials come from the Git installation you already use.

03

An optional CLI

Stop using madm whenever you like. The repository remains a standard Git repository with no conversion step.

Get started

Start clean or bring your history.

Install the latest archive for your platform from GitHub Releases, place madm on your PATH, and choose the workflow that matches your machine.

Start a new repository 
madm init
madm add .gitconfig
madm commit -m "Track Git configuration"
madm remote add origin <url>
madm sync
Use an existing repository 
madm clone <url>
madm status
madm compare

# Missing files are installed.
# Differing local files are preserved.
Note

madm init creates an empty repository. It never scans, stages, copies, moves, or commits files from your home directory.

Command reference

A small native surface.

Native commands cover dotfile-specific setup and safety. Everything else passes through to Git with the fixed repository and home work tree.

madm init

Initialize

Create an empty detached repository without touching home files.

Refuses an existing repository path.
madm clone <url>

Clone safely

Install missing tracked files and interactively review differences.

Keep local is always the default.
madm compare

See the full delta

Fetch and diff upstream against committed, staged, and unstaged state.

Does not alter HEAD, index, or files.
madm sync

Synchronize

Fetch, merge, resolve when needed, and push in one explicit workflow.

No rebase. No force push. No hidden stash.
madm resolve

Resume a merge

Choose local, upstream, merge tool, or skip for each unresolved path.

Enter skips without staging.
madm <git command>

Use Git directly

Run status, add, commit, diff, branch, stash, config, or a Git alias.

Arguments and exit codes pass through.

Inside sync

Both directions, one command.

Sync uses normal Git commits and merges. Each stage has a clear stopping point, and a rejected push never turns into a force push.

1 Check

Require a clean tracked work tree and attached branch.

2 Fetch

Update and pin the exact upstream commit being considered.

3 Protect

Detect incoming paths that would overwrite untracked content.

4 Merge

Fast-forward or create a normal merge commit. Never rebase.

5 Resolve

Make conflict choices explicit, or leave the merge resumable.

6 Push

Publish with an ordinary non-force push.

Safety by default

Your home is not a disposable checkout.

A dotfiles tool has an unusually large blast radius. madm favors reversible Git state, visible failures, and explicit user choices over clever automation.

Clone choices

Differing local files stay untouched unless you choose otherwise.

EnterKeep this local file
aKeep all remaining local files
rUse the remote version
mOpen the configured diff tool
qQuit and keep the rest local

Hard boundaries

  • madm clean is blocked to protect untracked home files.
  • Dirty tracked state must be committed before sync.
  • Incoming files cannot overwrite untracked or ignored content.
  • Repository internals are excluded from git add -A.
  • Force pushes and automatic history rewrites are never used.
  • Filesystem limitations are reported instead of hidden.

Project philosophy

The files in the home directory are the files under version control.

madm should be easy to adopt, easy to understand, and easy to leave. It adds a careful interface at the moments where bare Git is awkward or risky, then gets out of the way. New features must preserve the single work tree, plain-Git interoperability, explicit state, and cross-platform semantics.

Common questions

Nothing hidden.

The shortest answer is usually: it is standard Git, with careful defaults for a home-directory work tree.

Can I stop using madm later?

Yes. Remove the executable and use git --git-dir=<home>/.local/share/madm/repo.git. No migration or deinitialization is needed.

Does madm replace Git commands?

No. Unrecognized commands and Git aliases pass directly to Git. Native commands exist only for dotfile-specific setup, comparison, synchronization, and conflict handling.

Why must I commit before sync?

A clean tracked state makes the merge reversible and understandable. madm will not create a hidden stash or an automatic commit on your behalf.

Where does configuration live?

In Git. madm config is ordinary repository-local git config. There is no separate madm settings file.
